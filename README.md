## 项目目标

做一个完成度高、体验顺滑、规则正确、可持续扩展的数独 Web 游戏，优先实现：

- 稳定的核心玩法
- 清晰舒服的桌面端与移动端体验
- 正确的题目生成、校验与唯一解保证
- 完整的游戏辅助能力：计时、提示、错误高亮、撤销重做
- 良好的可维护性、测试覆盖和后续扩展空间

## 统一技术决策

为避免多个 agent 各做各的，建议全项目统一按下面方案执行：

- 前端：`React + TypeScript + Vite`
- 路由：如无多页需求，先不引入复杂路由
- 状态管理：优先 `useReducer + Context`，避免过早加重依赖
- 样式：`CSS Modules` 或清晰分层的原生 CSS，使用统一设计变量
- 测试：`Vitest + React Testing Library`
- 端到端：`Playwright`
- 存档：`localStorage`
- 题目逻辑：独立放在 `src/lib/sudoku`

## 建议目录结构

src/

  features/settings/

## 核心设计原则

- 逻辑与 UI 分离：数独生成、求解、校验不要塞进组件
- 单一数据源：棋盘状态、候选数、历史记录集中管理
- 可测试：核心算法必须脱离 UI 单测
- 可恢复：刷新后能恢复当前局面
- 先正确再炫：题目唯一解和交互正确性优先于复杂特效
